# K-JIT 프로토타입 구현계획

작성일 2026-10-08. [프로토타입-기획.md](./프로토타입-기획.md)를 구현하는 순서, 작업 단위, 완료 기준, 검증 방법, 일정, 위험을 정한다. 이 문서는 구현을 이어받는 사람이 처음부터 끝까지 따라갈 수 있도록 쓴다.

## 1. 인수인계 요약

### 1.1 확정된 것

- 주제는 K-JIT(선석 가용 확률 예측 기반 적시 입항 코파일럿)이다. 대표 Track은 해운 AX를 추천하되 미확정이다.
- 프로토타입은 정적 사이트로 만들고, 같은 소스에서 GitHub Pages용 다중 파일과 단일 HTML을 함께 빌드한다. 로그인·설치·API 키·실시간 호출이 없다.
- 저장소는 제출 직전(10/26)에 공개로 전환하고 Pages를 켠다. 제출 시점에 태그를 만들고 그 뒤 `main`을 동결한다.
- 구현 규모는 제약으로 두지 않는다. 다만 기획서의 사업 범위는 차년도 실행 기준을 유지한다.
- 화면 설계와 데이터 계약은 기획 문서를 따른다. 설계 토큰(색·서체·레이아웃·모션)은 기획 5절에 있고 팔레트는 검증을 마쳤다.

### 1.2 이미 있는 것

| 항목 | 위치 | 상태 |
|---|---|---|
| 분석 코드 | `kjit/` | A·B·C 완료. `queue_backtest.simulate()`는 `(F, M, qmat)`를 돌려준다 |
| 결과 요약 | `data/processed/*.csv`, `*.json` | git에 있음 |
| 중간 데이터·모델 | `data/processed/*.parquet`, `data/processed/models/` | git에 없음. 이 컴퓨터에는 있음. 다른 컴퓨터에서는 2절의 재현 명령으로 다시 만든다(약 30~40분, API 키 필요) |
| 원본 XML | `data/raw/vssl/` | git에 없음. 약 450MB |
| 인증키 | `.env` (`DATA_GO_KR_KEY`) | git에 없음. 세 API 모두 같은 키 |
| 수집기 | `kjit/snapshot.py`(2시간), `kjit/ulsan_positions.py`(5분) | 백그라운드 실행 중. PID는 `data/snapshot.pid`, `data/ulsan_positions.pid`. 끄지 않는다 |
| 웹 뼈대 | `web/` | Vite 8 + React 19 + TypeScript 6 템플릿 그대로. `d3-scale`, `d3-shape`, `d3-array`, `d3-interpolate`, `vite-plugin-singlefile` 설치됨. `App.tsx`는 템플릿 예제이므로 교체한다 |
| 문서 | `docs/` | 개요, 조사, 제안, 실측 A, 실측 BC, 프로토타입 기획, 이 문서 |

### 1.3 지켜야 할 것

- 숫자의 원천은 Python이다. 웹에서 연료 모델이나 정책 계산을 다시 만들지 않고, `export_web.py`가 쓴 값을 그대로 보여 준다. 예외는 CII 시뮬레이터와 정산 계산기처럼 사용자 입력으로 계산하는 도구이다.
- 화면의 수치는 `docs/실측-*.md`와 같아야 한다. 다르면 둘 중 틀린 쪽을 고친다.
- 시각은 KST로 고정해 표시한다. 브라우저의 시간대에 따라 달라지면 안 된다.
- `data/raw`, parquet, 모델, `.env`, 수집 로그, `web/node_modules`, `web/dist*`는 커밋하지 않는다(`.gitignore`에 있다).
- 팀원이 읽는 문서와 화면 문구에는 개인 호칭을 쓰지 않는다.
- 제출 태그 이후에는 `main`에 올리지 않는다.

## 2. 재현 명령

```bash
# Python (uv)
uv sync
uv run python -m kjit.fetch_calls --start 2025-10 --end 2026-09   # 원본 수집, 약 30분
uv run python -m kjit.parse_calls
uv run python -m kjit.measure_wait
uv run python -m kjit.savings
uv run python -m kjit.berth_dataset
uv run python -m kjit.forecast                                       # 모델 저장
uv run python -m kjit.queue_backtest                                 # 백테스트 표
uv run python -m kjit.export_web                                     # (WP1에서 추가) web/src/data/*.json

# Web
cd web
npm install
npm run dev            # 로컬 미리보기
npm run build          # dist/ (Pages)
npm run build:single   # dist-single/index.html (단일 파일, WP0에서 추가)
```

공공데이터포털 활용신청이 필요한 API: 해양수산부_선박운항정보, 해양수산부_항만시설사용정보, 울산항만공사_항내 선박위치정보. 모두 개발계정 자동승인이다.

## 3. 아키텍처

```
kjit/*.py ──(parquet)──> kjit/export_web.py ──> web/src/data/{cases,ports,evidence,cii_constants,contracts}.json
                                                        │ (정적 import, 번들에 포함)
                                                        ▼
                                          web/src (React 19 + TypeScript + D3 모듈)
                                                        │
                                   ┌────────────────────┴────────────────────┐
                                   ▼                                         ▼
                           web/dist/ (Pages, base './')          web/dist-single/index.html (단일 파일)
```

- 상태는 React `useReducer` 하나로 관리한다. 상태는 현재 화면, 선택 사례 id, 정보 조건, 위험 수준, 공개 여부, 항만 현황의 항만·날짜이다. 화면과 사례 id는 URL 해시와 양방향으로 동기화한다(`#decision/<id>`, `#ports/<항만>/<날짜>`, `#evidence`, `#cii`, `#contract`). 라우터 라이브러리는 쓰지 않는다.
- 차트는 React가 SVG를 그리고 D3는 척도(`d3-scale`), 경로(`d3-shape`), 보간(`d3-interpolate`)만 맡는다. 애니메이션은 `requestAnimationFrame` 훅으로 이전 값과 새 값을 보간한다. `prefers-reduced-motion`이면 보간을 건너뛴다.
- 스타일은 CSS 사용자 지정 속성과 일반 CSS 파일로 한다. Tailwind나 UI 키트는 쓰지 않는다. 단일 파일 크기를 작게 유지하기 위해서이다.
- 글꼴은 Google Fonts 링크 한 줄(IBM Plex Sans KR)이며, 실패 시 시스템 서체로 대체된다.
- 단일 파일 빌드는 `vite-plugin-singlefile`을 환경 변수로 켠다. `file://`에서 인라인 `type="module"` 스크립트가 실행되는지 WP0에서 먼저 확인한다.

## 4. 작업 단위

각 작업 단위는 독립적으로 완료 기준을 만족해야 하고, 끝날 때마다 커밋한다. 괄호 안은 예상 소요이다.

### WP0. 빌드 환경 (0.5일)

- `vite.config.ts`: `base: './'`, `process.env.SINGLE`이 있으면 `viteSingleFile()` 추가, 출력 폴더를 `dist-single`로.
- `package.json` scripts: `build:single`.
- `index.html`: 글꼴 링크, `<title>K-JIT 적시 입항 코파일럿</title>`, `color-scheme: light`.
- 템플릿 예제(`App.tsx`, `App.css`, `assets/`) 제거. `tokens.css`, `base.css` 작성.
- 확인: `npm run build:single` 결과를 Finder에서 더블클릭해 열었을 때 React가 렌더되고 콘솔 오류가 없다. 이 확인이 실패하면 단일 파일 전략을 먼저 고친다(스크립트를 `type="module"`에서 일반 스크립트로 바꾸는 옵션 검토).

### WP1. 데이터 내보내기 `kjit/export_web.py` (1일)

알고리즘:

1. `berth_dataset.build()`로 점유 표·대기 표·정박지 대기열을 만들고, 모델 묶음을 읽는다.
2. `queue_backtest.cases()`로 보정 구간(2026-06~07)과 시험 구간(2026-08~09)의 사례를 만든다.
3. 세 정보 조건마다:
   - 보정 구간을 `simulate()`로 돌려 PIT를 구한다. 결정 시각에 선석이 차 있던 사례만 쓴다.
   - 시험 구간을 `simulate()`로 돌려 `(F, M, qmat)`를 받는다.
   - 명목 수준 a ∈ {0.05, 0.10, …, 0.95}마다 재보정 수준 `recal(a) = quantile(PIT, a)`를 구하고, 사례마다 `quantile(F[i], recal(a))`를 `quantilesH`로 쓴다(결정 시각 기준 시간, 정렬).
   - 위험 수준 0.1/0.2/0.3/0.5마다 정책을 계산한다. 목표 시각 = 재보정 분위수, 지연 = `min(max(목표 − 원래 도착, 0), maxDelay)`, 권고 도착 = 원래 도착 + 지연, 속도 = 설계 속도 × H / (H + 지연), 연료·CO2 = `jit_saving_by_horizon`, 남은 대기 = `max(0, 실제 가용 − 권고 도착)`, 추가 유휴 = `max(0, 권고 도착 − 실제 가용) − max(0, 원래 도착 − 실제 가용)`.
   - 대기열 원소(M)마다 선박명·호출부호·상태·경과 또는 도착 시각·`qmat` 행·실제 출항 시각을 붙인다.
4. `featured`를 고른다. 조건은 선석이 차 있고, 선석계획 조건의 위험 수준 0.1 정책에서 지연 6시간 이상, 추가 유휴 1시간 이하, 실제 대기 12시간 이상인 사례 가운데 항만별 절감 상위 2건, 그리고 추가 유휴 2시간 초과 사례 1건(실패 사례)이다.
5. `ports.json`, `evidence.json`을 만든다. `evidence.json`의 표는 기존 CSV를 그대로 읽는다. 대기 분포 구간은 `berth_waits.parquet`의 화물선 기준이다.
6. `cii_constants.json`은 상수와 출처를 손으로 작성한다. `contracts.json`의 발췌와 메모는 WP6에서 채운다.

검증:

- 정책별 연료·CO2 합계가 `data/processed/queue_backtest.csv`의 같은 조건·정책과 소수 첫째 자리까지 같다.
- 사례 수 1,253, `busyAtTau` 참 897.
- 파일 크기 합계 3MB 이하.
- 재생 가능하도록 난수 시드를 고정한다(`simulate()` 내부 시드 0).

### WP2. 항차 결정 화면 (2~3일)

구성 요소와 완료 기준은 기획 4.1절을 따른다. 구현 순서는 데이터 로딩·사례 선택 → 머리말 → 토글 → 대기열 패널 → 분포 띠(정적) → 권고 카드 → 실제 결과 패널 → 보간 모션 → 호버 십자선·툴팁 → 표 보기 → 휴대폰 레이아웃 → 키보드 점검이다.

분포 띠 세부:

- x 척도: 시간(시, 결정 시각 기준) → 픽셀. 눈금은 6시간 간격, 라벨은 날짜가 바뀌는 눈금에 `9/1`, 나머지는 `06시`처럼 KST로 쓴다.
- 띠는 분위수 쌍(5–95, 20–80)의 `d3-shape` area로 그린다. y 축은 "이 시각까지 선석이 빌 확률"(0~1)이다. 즉 띠가 아니라 누적분포 곡선 하나를 그리고, 곡선 아래를 두 단계로 칠하는 방식도 가능하다. 둘 중 하나를 WP2 초반에 스케치해 보고 더 읽기 쉬운 쪽을 택하되, 호버 읽기("이 시각까지 선석이 빌 확률 N%")는 반드시 제공한다.
- 표식: 원래 도착(흐린 잉크), 권고 도착(자홍, 위험 수준에 따라 이동), 최대 지연 한계(격자선 색), 실제 가용 시각(기본 잉크, 공개 후).
- 툴팁은 `textContent`로 넣는다. 선박명은 외부 데이터이다.

### WP3. 항만 현황 화면 (1일)

기획 4.2절. 날짜 목록은 61일을 세로 목록으로 두고 선택을 굵은 체크로 표시한다. 목록 행의 "이 항차 열기"는 해시를 바꾸어 항차 결정 화면으로 이동한다.

### WP4. 근거 화면 (1일)

기획 4.3절. 차트는 막대 두 종류(대기 분포, 상한 대비 절감)이며, 모두 표 보기를 갖는다. 숫자는 `evidence.json`에서만 읽는다.

### WP5. CII 시뮬레이터 (1일)

기획 4.4절. 상수는 IMO G2(MEPC.353(78)) 기준선 계수와 G4(MEPC.354(78)) 등급 경계에서 가져와 `cii_constants.json`에 출처 문구와 함께 둔다. 기억에 의존해 쓰지 않고 결의 본문에서 옮긴다. Z 표는 MEPC.400(83) 부속서 Table 1 값이다.

### WP6. 계약·정산 화면 (1일)

기획 4.5절. 합성 계약 발췌 세 개를 영어로 작성한다. 실제 BIMCO 조항 전문은 저작권이 있으므로 그대로 싣지 않고, 조항의 구조를 따른 합성 문장을 쓴다. 해석 메모는 LLM으로 미리 생성해 사람이 검토한 뒤 넣고 "LLM 사전 생성, 사람 검토 필요"를 표시한다.

- 화면: 작업 단위마다 로컬 미리보기를 캡처해 확인한다. 기획 9절 체크리스트를 WP7에서 전부 돈다.
- 수치 대조: 항차 결정 화면에서 대표 사례 세 건을 골라 `queue_backtest_cases.parquet`의 값과 비교한다. 근거 화면의 표는 실측 문서와 비교한다.
- 코드: `npm run build`가 TypeScript 오류 없이 통과한다. `npm run lint`를 통과한다.
- 크기: 단일 HTML 5MB 이하.

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| 단일 HTML이 `file://`에서 실행되지 않음 | WP0에서 먼저 확인한다. 실패하면 플러그인 옵션으로 일반 스크립트 출력을 쓰거나, 데이터를 `<script type="application/json">`으로 넣고 읽는다 |
| JSON이 커서 번들이 무거움 | 분위수 개수 축소, 숫자 반올림, 사례를 선석이 차 있던 897건으로 제한 |
| 글꼴 미로드 | 시스템 한글 서체 대체를 전제로 레이아웃을 잡는다 |
| 브라우저 시간대 차이 | 모든 표시는 `Asia/Seoul` 고정 포맷터를 쓴다. `Date`의 로컬 포맷 메서드를 쓰지 않는다 |
| 사파리 SVG 보간 성능 | 보간 대상은 경로 두 개와 표식 세 개로 제한한다 |
| 데이터 재생성 시 숫자 변동 | 난수 시드 고정, 재생성 후 문서 수치 재대조 |
| 공개 전환 뒤 Pages 활성화 지연 | 10/26에 전환해 이틀 여유를 둔다. 임시 공개 저장소로 리허설한다 |
| 공고의 첨부 용량 제한 미확인 | 주최 측 문의에 포함. 단일 HTML 5MB, 영상 50MB 이하를 목표로 한다 |

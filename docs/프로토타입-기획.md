# K-JIT 프로토타입 기획

작성일 2026-10-08. 공모전 제출용 프로토타입의 목적, 화면, 데이터 계약, 디자인 시스템, 표기 규칙, 배포·동결 절차를 정한다. 구현 순서와 작업 단위는 [구현계획.md](./구현계획.md)에 둔다. 주제 배경과 근거 수치는 [K-JIT-개요.md](./K-JIT-개요.md)를 따른다.

## 1. 목적과 평가 연계

공고의 프로토타입 가점 기준은 "제출한 프로토타입이 제안 아이디어와 일관되게 연계되고, 핵심 기능과 사용자 흐름을 구체적으로 구현하며 실현 가능성을 뒷받침하는가"(최대 10점)이다. 가점을 주지 않는 조건은 "파일 손상, URL 접속 불가, 로그인·설치·권한 승인 필요"이며, 마감 후에는 파일과 URL 내용을 수정할 수 없다.

프로토타입이 증명해야 하는 것은 세 가지이다.

1. **핵심 흐름이 끝까지 이어진다.** 입항 전 결정 시각에 선석이 비는 시각을 확률로 예측하고, 위험 수준에 맞는 도착 시각과 속도를 권고하고, 절감량과 정산 영향을 보여 준 뒤, 그 항차의 실제 결과를 공개한다.
2. **숫자가 실제 데이터에서 나온다.** 모든 사례는 2026-08~09 해양수산부 입출항 신고를 재생한 것이며, 화면에 "실데이터 재생"임을 적는다.
3. **제안서와 같은 그림을 쓴다.** 기획서 2.3절(활용 시나리오 및 화면 구성)의 그림은 이 프로토타입의 화면 캡처로 만든다. 그래서 프로토타입을 기획서보다 먼저 완성한다.

제출 형태는 세 가지를 모두 준비한다.

| 형태 | 용도 | 비고 |
|---|---|---|
| 공개 URL (GitHub Pages) | 심사위원이 클릭 한 번에 여는 기본 경로 | 저장소를 공개로 전환한 뒤 활성화 |
| 단일 HTML 파일 | 더블클릭으로 열리는 백업. 데이터·스크립트·스타일을 한 파일에 포함 | 제출 zip에 포함 |
| 화면 녹화 영상 (2~3분) | 둘 다 열리지 않을 때의 보험 | mp4, 제출 zip에 포함 |

## 2. 사용자와 핵심 흐름

주 사용자는 중소 탱커·가스·벌크 선사의 운항 담당자이다. 보조 사용자는 용선자(화주), 선박대리점, 항만공사 선석 담당이다. 심사위원은 이 사용자 가운데 운항 담당자의 자리에서 화면을 본다.

핵심 흐름은 다섯 단계이다.

1. 운항 담당자가 입항 24시간 전(내항은 항해시간 이내)에 항차를 연다.
2. 시스템이 목적 선석의 점유 선박과 대기 순번을 보여 주고, 선석이 비는 시각의 분포를 그린다.
3. 담당자가 정보 조건(공개 데이터만 / 대기 순번 공유 / 선석계획 공유)과 위험 수준(0.1 / 0.2 / 0.3 / 0.5)을 고른다.
4. 시스템이 권고 도착 시각(RTA), 권고 속도, 절감 연료·CO2, 체선료 정산 영향, 선장 지시문 초안을 보여 준다.
5. 담당자가 "실제 결과 보기"를 눌러 그 항차의 실제 선석 가용 시각과, 현행 대비 남은 대기·추가 선석 유휴를 확인한다.

상단 사례 선택: 항만 필터와 사례 목록(날짜순)을 둔다. 첫 진입 시 대표 사례(`featured`)가 열린다. 대표 사례에는 권고가 잘 맞은 사례와 늦게 도착해 선석이 비었던 사례를 함께 넣는다.

구성 요소:

- **항차 머리말.** 선박명(호출부호), 선종, 총톤수, 내항·외항, 항만, 목적 선석, 정박지, 원래 도착(A0), 결정 시각(τ), 권고 범위(H시간 전).
- **정보 조건 토글.** 세 조건 사이를 바꾸면 대기열 목록과 분포 띠가 함께 바뀐다. 조건마다 한 줄 설명을 붙인다. 예: "공개 데이터만: 지금 선석에 붙어 있는 배만 안다."
- **위험 수준 토글.** 0.1 / 0.2 / 0.3 / 0.5. 설명: "0.1은 선석이 비어 있을 확률이 10%일 때 도착한다. 숫자가 작을수록 보수적이다."
- **선석 대기열 패널.** 조건에 따라 보이는 선박이 다르다.
  - 접안 중(●): 선박명, 접안 후 경과 시간, 남은 체류 예측 중앙값과 10~90% 구간.
  - 대기(○, 대기 순번·선석계획 조건): 선박명, 정박지 도착 시각, 체류 예측 중앙값과 구간.
  - 계획(◌, 선석계획 조건): 선박명, 도착 예정 시각(실제 입항 시각 사용), 체류 예측.
  - 선석이 비어 있으면 "결정 시각에 선석이 비어 있음"을 표시하고 권고는 "원래 일정 유지"로 둔다.
- **분포 띠(fan chart).** x축은 결정 시각부터의 시간(시)이며 날짜·시각 눈금을 KST로 표시한다. 범위는 τ부터 "τ+96시간"과 "실제 가용 시각·최대 지연 도착 중 늦은 것" 가운데 큰 쪽까지이다. 5~95% 구간을 연한 띠, 20~80% 구간을 중간 띠, 50%를 선으로 그린다. 수직 표식은 원래 도착(A0), 권고 도착(RTA, 위험 수준에 따라 이동), 최대 지연 한계(최저 속도), 공개 후 실제 선석 가용 시각이다. 호버하면 수직 십자선이 가장 가까운 시각에 붙고 "이 시각까지 선석이 빌 확률 N%"를 읽어 준다. 표 보기 토글로 분위수 표를 같은 자리에 보여 준다.
- **권고 카드.** 권고 도착 시각, 지연 시간, 권고 속도(설계 속도 대비), 절감 연료·CO2, 체선료 메모(BIMCO JIT 조항 2021 기준 "연장 항해 N시간에 감액 체선료율 적용"), 선장 지시문 초안(한·영 템플릿, "템플릿 자동 생성" 표기). 위험 수준 네 가지의 비교 표(지연, 절감, 남은 대기, 추가 유휴)를 접이식으로 둔다.
- **실제 결과 패널.** 버튼을 누르면 실제 선석 가용 시각 표식이 띠 위로 쓸려 들어오고, 현행 대기(원래 도착 기준), 권고 후 남은 대기, 추가 선석 유휴, 대기열 선박의 실제 출항 시각이 표시된다. 다른 조건·위험 수준으로 바꿔도 공개 상태는 유지한다.

예외 상태:

- 선석이 결정 시각에 비어 있는 사례(전체의 약 28%)는 분포가 한 점이므로 띠 대신 "결정 시각에 이미 비어 있음"을 쓴다.
- 원래 도착이 실제 가용 시각보다 늦은 사례는 현행 대기 0시간이며, 권고도 원래 일정 유지이다.
- 데이터가 없는 조합은 만들지 않는다. 모든 사례는 세 조건을 다 갖는다.

완료 기준: 대표 사례가 첫 화면에 뜨고, 조건·위험 수준 토글에 따라 띠와 권고가 바뀌며, 실제 결과 공개가 동작하고, 키보드만으로 모든 조작이 가능하고, 휴대폰 폭(375px)에서 세로로 쌓여 읽힌다.

### 4.2 항만 현황

목적: 항만과 날짜를 고르면 그날 입항한 선박 목록을 보여 주고, 항차 결정 화면으로 들어가게 한다.

- 항만 탭: 대산, 울산, 광양, 여천.
- 날짜 선택: 2026-08-01~09-30을 목록으로 둔다(달력 격자 대신 목록, 선택은 굵은 체크로 표시).
- 요약 띠: 그날 입항 n척, 정박지 경유 m척, 평균 선석 대기 h시간(추정 가능한 항차 기준).
- 목록: 입항 시각, 선박명, 선종, 경로(직접 접안 / 정박지→선석 / 정박지 체류만), 첫 계선시설, 사례 열기. 작업·지원·여객선은 제외한다.
- 선택: 그날의 선석 보드(선석 × 시간 점유 막대)를 목록 위에 둘 수 있다. 우선순위는 낮다.

완료 기준: 네 항만·61일 모두 목록이 뜨고, 사례 열기가 항차 결정 화면으로 해시와 함께 이동한다.

### 4.3 근거

목적: 실측 문서의 수치를 화면에서 그대로 확인하게 한다. 숫자는 [실측-A](./실측-A-정박지대기-2026-10-08.md)와 [실측-BC](./실측-BC-선석예측-JIT백테스트-2026-10-08.md)와 일치해야 한다.

- 정박지 대기: 항만별 요약 표(정박지→선석 비율, 대기 중앙값, p75, p90, 12시간 이상 비율)와 대기 분포 막대(구간 0~2, 2~6, 6~12, 12~24, 24~48, 48~96, 96시간 이상).
- 선석 가용 예측: 기준선과 모델의 MAE·pinball·80% 구간 적중률·평균 폭 표.
- JIT 결정 백테스트: 정보 조건 × 위험 수준의 상한 대비 절감 막대(세 조건을 한 축에), 추가 선석 유휴 표. 완전 정보 상한을 기준선으로 표시한다.
- 데이터와 방법: 출처 API 세 개, 기간, 항차 수, 대기 추정 방법 한 문단, 한계 목록(하한 추정, 적중률 미달, 선석 기지 가정, 연료 계수 근사).

완료 기준: 표의 모든 숫자가 문서와 같고, 차트마다 표 보기가 있다.

### 4.4 CII 시뮬레이터

목적: 정박지 대기를 줄이면 선박의 연간 CII 등급이 어떻게 바뀌는지 2027~2030 기준으로 보여 준다.

- 입력: 선종(벌크선, 탱커, 가스운반선, 컨테이너선), 용량(DWT 또는 GT, 선종 규칙에 따름), 연간 항해거리(해리), 연간 연료(톤)와 연료 종류(VLSFO/HFO/MGO), 연간 정박지 대기 시간(시간)과 대기 중 일일 연료(톤/일).
- 계산: attained CII = 연간 CO2 / (용량 × 항해거리). 필요 CII = 기준선 × (1 − Z). 기준선 계수(a, c)와 등급 경계(d1~d4)는 IMO 지침 G2(MEPC.353(78))와 G4(MEPC.354(78))에서 가져와 상수 파일에 출처와 함께 둔다. Z는 2023 5%, 2024 7%, 2025 9%, 2026 11%, 2027 13.625%, 2028 16.250%, 2029 18.875%, 2030 21.500%이다(MEPC.400(83)).
- 출력: 연도별 필요 CII와 등급 경계, 대기 제거 전후의 attained CII와 등급(A~E). "대기 제거"는 입력한 대기 시간만큼의 연료를 빼고 거리는 그대로 두는 단순 가정임을 적는다.
- 기본값: 실측 문서의 울산 탱커 평균값을 참고해 넣되, 모든 기본값에 "예시"를 붙인다.

완료 기준: 입력을 바꾸면 즉시 등급이 다시 계산되고, 상수의 출처가 화면에 보인다.

### 4.5 계약·정산

목적: 감속의 이익과 손해가 선주·용선자 사이에서 어떻게 나뉘는지 계산하고, 용선계약에서 관련 조항을 찾는 모습을 보여 준다.

- 계약 조항 확인(사전 생성): 합성 용선계약 발췌 세 개를 둔다. (1) BIMCO JIT 도착 조항이 있는 계약, (2) 신속 항해 의무만 있는 계약, (3) 가상 도착(virtual arrival) 조항이 있는 계약. 각 발췌에서 관련 문장을 강조하고 "이 조항은 용선자의 서면 요청으로 감속을 허용한다" 같은 해석 메모를 붙인다. 메모는 LLM으로 미리 생성해 넣고 "LLM 사전 생성, 사람 검토 필요"를 표시한다. 실시간 LLM 호출은 하지 않는다.
- 정산 계산기: 입력은 체선료율(USD/일), JIT 조항의 감액 비율(%), 연료 단가(USD/톤), 항차의 지연 시간과 절감 연료(항차 결정 화면에서 넘어오거나 직접 입력). 출력은 선주와 용선자 각각의 현행 대비 변화(연료비, 체선료 수입·지출)와 합계. 기본 요율은 "예시"로 표시한다.
- 선장 지시문·용선자 요청서 초안: 한국어·영어 템플릿. 권고 속도, RTA, 근거(선석 가용 분포 요약), 조항 인용.

완료 기준: 계산기가 항차 결정 화면의 값을 받아 동작하고, 발췌 세 개의 강조와 메모가 표시되며, 사전 생성 표기가 보인다.

## 5. 디자인 시스템

주제의 시각 어휘는 해도(nautical chart)와 선석 계획판이다. 시간을 가로축으로 두는 판 위에 확률의 띠가 흐르고, 해도에서 항로표지를 표시하는 자홍색이 권고 도착 시각 하나에만 쓰인다. 기억에 남을 요소는 분포 띠와 권고 표식이고, 나머지는 조용하게 둔다.

### 5.1 색

| 역할 | 값 | 비고 |

### 5.2 글자

- 서체: IBM Plex Sans KR(Google Fonts). 한글과 라틴을 한 가족으로 쓴다. 네트워크가 없을 때는 시스템 한글 서체(Apple SD Gothic Neo, Malgun Gothic)로 대체되며 레이아웃이 깨지지 않아야 한다.
- 크기: 본문 15px/1.6, 보조 13px, 머리말 선박명 22px, 권고 도착 시각 28px 세미볼드. 한 화면에 큰 숫자는 권고 도착 시각 하나만 둔다.
- 숫자: 시각·표 열에는 `font-variant-numeric: tabular-nums`, 큰 숫자는 비례 숫자.
- 라벨: 문장체, 전부 대문자 라벨과 가운뎃점 연결 문자열을 쓰지 않는다. 라벨 위에 작은 안내 문구를 덧붙이지 않는다.

### 5.3 레이아웃

- 최대 폭 1,280px, 좌측 정렬. 항차 결정 화면은 세 열(대기열 280px / 띠 가변 / 권고 300px)이며 1,100px 아래에서는 띠 → 권고 → 대기열 순으로 세로로 쌓인다. 휴대폰은 16px 가터, 가로 스크롤 없음.
- 패널은 그림자 카드가 아니라 면색 차이와 1px 선으로 나눈다. 모서리 반경은 패널 6px, 버튼 4px 두 가지만 쓴다.
- 번호 매기기는 실제 순서가 있는 곳(대기 순번, 핵심 흐름 단계)에만 쓴다.

### 5.4 모션

- 사용자가 조작했을 때만 움직인다. 정보 조건·위험 수준을 바꾸면 띠와 표식이 240ms 동안 보간되며 옮겨 간다. "실제 결과 보기"는 결정 시각에서 실제 가용 시각까지 수직선이 600ms 동안 쓸려 가는 한 번의 연출이다.
- 페이지 진입 애니메이션, 카드 호버 효과는 넣지 않는다.
- `prefers-reduced-motion`이면 보간 없이 즉시 바뀐다.

### 5.5 글쓰기

- 운항 담당자의 말로 쓴다. 선석, 정박지, 항차, 권고 도착(RTA), 노트, 체선료처럼 현장 용어를 그대로 쓰고 풀어 쓰지 않는다.
- 버튼은 일어나는 일을 적는다. "실제 결과 보기", "이 항차 열기", "표로 보기".
- 빈 화면과 예외는 이유와 다음 행동을 적는다. "결정 시각에 선석이 비어 있어 권고가 없습니다. 원래 일정대로 도착합니다."
- 과장하지 않는다. "절감"은 실측 재생 결과이고 "예시"·"가정"·"사전 생성"은 그렇게 적는다.

### 5.6 접근성 바닥선

- 포커스 링이 보이고, 토글·버튼·목록은 키보드로 조작된다.
- 두 계열 이상이 있는 차트에는 범례가 있고, 차트마다 표 보기가 있다.
- 색만으로 뜻을 전하지 않는다. 표식에는 라벨, 막대에는 숫자를 붙인다.

## 6. 데이터 계약

Python 파이프라인(`kjit/export_web.py`)이 `web/src/data/`에 JSON을 쓰고, 웹 앱은 그 파일을 정적으로 가져와 번들에 넣는다. 런타임 네트워크 요청은 글꼴 하나뿐이다. 시각은 모두 `+09:00` 오프셋을 가진 ISO 8601 문자열이며, 화면은 `Asia/Seoul`로 고정해 표시한다. 시간 길이는 시(h) 단위 소수 첫째 자리, 연료·CO2는 톤 소수 첫째 자리이다.

## 7. 정직성·표기 규칙

- 모든 화면에 "2026-08~09 해양수산부 입출항 신고 실데이터 재생"을 고정 표시한다.
- 재생 결과(예측·권고·절감·실제 결과)와 가정값(연료 계수, 요율, CII 입력 기본값)을 시각적으로 구분한다. 가정값에는 "예시" 또는 "가정"을 붙인다.
- LLM으로 미리 만든 문장에는 "LLM 사전 생성, 사람 검토 필요"를 붙인다. 템플릿 문장에는 "템플릿 자동 생성"을 붙인다.
- 한계는 근거 화면에 그대로 적는다. 선석 대기가 하한 추정이라는 점, 80% 구간 적중률이 목표에 못 미친다는 점, 모든 조건이 목적 선석을 안다고 가정한다는 점, 선석계획 조건은 앞 순번의 도착을 안다고 가정한다는 점을 뺀 채 보여 주지 않는다.
- 화면의 수치는 문서의 수치와 같아야 한다. 데이터를 다시 뽑으면 문서도 같이 고친다.

## 9. 검수 체크리스트

- 크롬, 엣지, 사파리, 모바일 사파리에서 다섯 화면이 열린다.
- 단일 HTML을 더블클릭(`file://`)으로 열었을 때 콘솔 오류가 없고 데이터가 보인다.
- 네트워크를 끊어도 글꼴만 대체되고 화면이 유지된다.
- 해시 링크로 특정 사례를 열 수 있다.
- 항차 결정 화면의 숫자 세 사례를 `data/processed/queue_backtest_cases.parquet`와 대조한다.
- 근거 화면의 표를 실측 문서와 대조한다.
- 키보드만으로 모든 조작이 된다. 포커스가 보인다.
- `prefers-reduced-motion`에서 보간이 꺼진다.
- 번들 크기와 단일 HTML 크기를 기록한다.
